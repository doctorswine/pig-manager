# 피그매니저 기능 개발

작업 전에 저장소 루트의 `docs/PROJECT_HANDOFF.md`를 전부 읽어 현재 상태와 확정 규칙을 확인한다. 사용자의 최신 지시가 문서보다 우선한다.

## 화면 패턴

- 기존 대시보드와 모돈 생산관리 화면의 사이드바, 상단 농장 표시, 카드, 번식 탭, 조회·정렬·체크박스 삭제 패턴을 유지한다.
- 모돈번호와 이각번호는 별도 문자열로 다시 입력하게 하지 말고 가능한 한 전입 또는 분만 기록 선택 목록에서 연결한다.
- 계산값은 읽기 전용으로 보여주되 사용자가 직접 나눠 입력해야 하는 값은 합계 검증과 함께 수정 가능하게 한다.
- 새 목록 화면은 작업일·모돈번호·이각번호 정렬과 오름차순·내림차순을 제공한다.
- 참고 화면의 모든 필드를 복제하지 않는다. 사용자가 제외하거나 변경한 항목을 우선한다.

## 데이터와 업무 규칙

- 현재 프로토타입은 `app/production/sows/_data/`의 타입·기본 데이터와 브라우저 `localStorage`를 사용한다.
- 데이터 연결 순서는 전입 → 초발정 → 교배 → 임신사고 → 분만 → 포유자돈 → 이유다. 독립 입력보다 이전 기록 선택과 자동 연결을 우선한다.
- 분만예정일은 교배일을 1일차로 계산한 115일째다.
- 포유두수는 실산, 생시도태, 분만 시 양자 이동, 포유자돈 증감 기록을 순서대로 반영한다.
- 이유 후 잔여두수는 0이 아니어도 유효하다. 재포유 두수는 잔여두수를 초과할 수 없다.
- 양자 상대 모돈은 분만 기록이 있는 다른 모돈이어야 한다.
- 현재 프로토타입 목록에서는 잘못된 기록을 체크박스로 선택 삭제할 수 있다. Supabase 전환 시 물리 삭제 대신 정정·취소 이력을 남기는 제품 원칙을 적용한다.

## 엑셀 일괄등록

- 기존 교배·분만·이유 구현처럼 화면 상단에 `데이터 업로드`와 `양식 다운로드`를 둔다.
- 다운로드 양식은 `public/templates/`, 파서는 `app/api/<기능>/import/route.ts`, 검증 스크립트는 `scripts/`에 둔다.
- 필수 열, 날짜, 음수가 아닌 두수, 파일 내 중복을 서버에서 검증한다. 기존 전입·분만·포유 기록과의 관계 및 기존 기록 중복은 클라이언트에서 검증한다.
- 업로드 결과는 등록 건수와 확인이 필요한 행을 사용자에게 보여준다. `.xlsx`, 5MB 이하, 최대 1,000행 기준을 유지한다.
- 식별번호는 텍스트로 보존하고 날짜는 `yyyy-mm-dd`, 두수는 정수, 체중은 숫자로 다룬다.

## 완료 조건

1. 관련 타입·화면·API·양식이 같은 업무 규칙을 사용한다.
2. `npm run build`가 성공한다.
3. 예시 엑셀을 API에 업로드해 정상 행과 오류 행 처리를 확인한다.
4. 실제 브라우저에서 핵심 필드, 자동 계산, 탭 이동, 콘솔 오류 유무를 확인한다.
5. 확정된 새 규칙과 구현 상태를 `docs/PROJECT_HANDOFF.md`에 반영한다.
