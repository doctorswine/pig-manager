# 개발 로드맵

## 1단계 — 제품 범위와 모델

- [x] 사용자와 MVP 업무 범위 정의
- [x] 핵심 엔터티와 보안 원칙 정의
- [x] 모돈 중심 번식농장을 첫 대상으로 확정
- [x] 화면 흐름과 데이터 모델 초안 작성
- [ ] 실제 농장 운영 방식에 맞춘 용어·필수 입력값 검토
- [x] 생산관리 1차 메뉴 4개 확정
- [x] 모돈개체관리 2차 메뉴 확정
- [ ] 생산관리 영역별 세부 메뉴 확정

완료 조건: 첫 사용자 시나리오와 핵심 엔터티가 합의되어 구현 중 큰 구조 변경이 필요하지 않다.

## 2단계 — 프로젝트 기반

- [x] Next.js App Router 프로젝트 생성
- [x] TypeScript와 반응형 UI 기본 구성
- [x] 예시 데이터 기반 농장 대시보드 구현
- [ ] Vercel 프로젝트 연결
- Supabase 프로젝트 생성 및 Auth 연결
- 환경 변수 검증
- 로그인, 보호 경로, 앱 셸 구현

완료 조건: 로그인 후 빈 대시보드에 접근하고 Vercel 미리보기 배포가 성공한다.

## 3단계 — 멀티테넌트와 시설

- 조직, 멤버십, 농장, 돈사, 돈방 스키마
- 역할별 RLS 정책
- 농장 선택과 시설 관리 화면
- 권한 및 테넌트 격리 테스트

완료 조건: 서로 다른 농장 사용자가 상대 농장 데이터를 API로도 읽거나 수정할 수 없다.

## 4단계 — 개체와 번식

- 모돈·웅돈 등록/검색/상세 이력
- 교배, 임신진단, 분만, 이유 이벤트
- 예정일 자동 계산
- 모바일 빠른 입력

완료 조건: 모돈 한 마리의 번식 사이클을 처음부터 끝까지 기록할 수 있다.

## 5단계 — 작업과 대시보드

- 이벤트 기반 예정 작업 생성
- 담당자·상태·지연 관리
- 핵심 생산 KPI
- 기간/농장/돈사 필터

완료 조건: 현장 작업자와 관리자의 일일 운영 흐름이 연결된다.

## 6단계 — 그룹, 건강, 재고

- 자돈·육성·비육 그룹과 이동/두수 대사
- 치료·백신과 약품 재고
- 휴약기간 및 재고 부족 경고

## 7단계 — 운영 준비

- 감사 로그, 백업·복구 절차
- 데이터 가져오기/내보내기
- 성능·보안·접근성 점검
- 실제 농장 파일럿과 개선

## 다음 작업

1. 실제 농장 기준으로 용어·필수 입력값을 검토한다.
2. Supabase와 Vercel 프로젝트를 준비한다.
3. 프로젝트를 생성하고 첫 로그인까지 구현한다.
4. 멀티테넌트 RLS와 시설 관리부터 구현한다.
